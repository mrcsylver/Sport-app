# Iron League for iOS

A native SwiftUI app on the same Supabase backend as the web app. Same
database, same rules, same scores — a person can log on the phone and their
friend sees it on the web a second later, because neither app owns any logic
that matters. Everything that decides a number lives in Postgres.

This is **not** a wrapper around the website. It is a rebuild for a phone:
depth instead of flat panels, motion instead of static tables, real haptics,
and rows that visibly move when a rank changes.

---

## Building it

You need a Mac, Xcode 15 or newer, and the Apple developer account you already
have signed in.

```bash
brew install xcodegen        # once
cd ios
xcodegen                     # writes IronLeague.xcodeproj from project.yml
open IronLeague.xcodeproj
```

Then in Xcode:

1. Select the **IronLeague** target → **Signing & Capabilities**.
2. Pick your team. Automatic signing will do the rest.
3. If `com.ironleague.app` is taken, change the bundle id to something of
   your own — it is one line in `project.yml`, then run `xcodegen` again.
4. Choose an iPhone (or a simulator) and press ⌘R.

Xcode resolves the one dependency, [supabase-swift][], on the first build.
That takes a minute; nothing else is fetched.

[supabase-swift]: https://github.com/supabase/supabase-swift

### Why the project file is generated

`IronLeague.xcodeproj` is not in git. It is produced from `project.yml`, which
is fifty readable lines instead of a thousand lines of XML that conflict every
time two people touch them. Add a file, run `xcodegen`, done — there is no
"remember to add it to the target" step.

## What is where

```
ios/IronLeague
├── App/            the entry point, the phase switch, the tab bar
├── Core/           config, models, the API, and the one Session object
├── Design/         theme, motion, components, banners, icons
└── Features/
    ├── Live/       the leaderboard — the reason the app exists
    ├── Log/        the log sheet and the exercise picker
    ├── Duels/      weekly rivalries and 1-v-1 challenges
    ├── Hall/       finished weeks, then the streak table
    ├── Stats/      your grade, your numbers, your badges
    ├── Leagues/    leagues, profile, league settings, shop
    └── Onboarding/ name, then league
```

Four rules the code follows:

**Nothing talks to Supabase except `Core/API.swift`.** One typed method per
Postgres function. When the schema changes there is exactly one file to fix.

**Nothing is stored that can be derived.** Divisions, grades, streaks,
rivalries, badges and raid progress are all computed on read, on the server,
from the workouts that already exist. There is no award step and nothing to
backfill — a badge added next month retro-grants itself to everyone who
already qualified.

**The server scores, the app previews.** `Session.points(…)` mirrors
`calc_points()` exactly so the log sheet can show a number as you turn the
dial, but the value that counts is stamped by a trigger on insert. If the two
ever disagree, the server is right.

**One `Session` object.** Views read it; nothing else writes to it. The app is
small enough that one source of truth beats five coordinated ones.

## The artwork

Both apps draw from the same vendored [game-icons.net][] set (CC BY 3.0), so an
emblem chosen on the web is the same drawing here — not a lookalike SF Symbol.
The web renders them as inline SVG; iOS has no SVG renderer, so they are
converted to vector PDFs in the asset catalog:

```bash
python3 tools/build_ios_icons.py     # 154 icons + Design/IconSets.swift
python3 tools/check_ios_icons.py     # proves the conversion is right
python3 tools/build_ios_appicon.py   # the app icon, from the same pipeline
```

`Design/IconSets.swift` is generated by the same script that writes the assets,
from the same source the web app reads, so the two sets cannot drift apart.
Do not edit it by hand.

The checker exists because there is no SVG or PDF renderer in the environment
that generates these. Instead of looking at the result it proves it: every path
parses, arc flags are read the way the spec says, the cubic approximation of
each arc is compared against the true ellipse (worst case: 0.05 units in 512),
and any icon can be scan-filled into ASCII to be looked at:

```bash
python3 tools/check_ios_icons.py wolf-head spartan-helmet
```

[game-icons.net]: https://game-icons.net

### Banners

The 32 banner skins are drawn, not downloaded — same keys and same colours as
the web app's CSS, rebuilt in a `Canvas` in `Design/BannerSkin.swift`. Nothing
to fetch, they re-theme with the app, and the motion is part of the artwork
rather than a keyframe fighting the scroll.

## Checking it without a compiler

```bash
python3 tools/check_ios_swift.py
```

This cannot type-check anything — it is not a Swift compiler. What it catches
is the class of mistake that has actually broken this project before: a view
referenced but never written, a type declared twice, a file whose braces do not
close. Run it after adding files; it is a second, not a substitute for ⌘B.

## Things worth knowing before you change something

**The timezone is not cosmetic.** `Config.timeZone` must match
`app_timezone()` in `supabase/schema.sql`. Week boundaries, rest days and
bounty dates are all computed against it on the server; if the app disagrees,
the countdown lies to people. Making this per-league is written down in
`ROADMAP.md` as the blocker for launching outside one country.

**The anon key in `Config.swift` is meant to be public.** The database is
protected by row-level security and `SECURITY DEFINER` functions, not by
hiding a string that ships inside every copy of the app anyway.

**Anonymous auth, restore codes, no accounts.** Same as the web app: signing
in creates a device-bound identity, and an eight-character restore code is the
only way to move a profile to another phone. Real accounts (phone or email)
are the migration written down in `ROADMAP.md`.

**iOS 17 is the floor.** `@Observable`, `contentTransition(.numericText:)` and
`symbolEffect` all need it. `MeshGradient` would have been tidier than the
`Canvas` in `LivingBackground.swift`, but that is iOS 18 and not worth the
users it would cost.
