# The browser tests

Twenty-nine Playwright runs against the real `index.html` and `admin.html`, with
Supabase replaced by `mock-supabase.js` — a hand-written stand-in that keeps a
database in `localStorage` and answers the same RPCs the server does.

```bash
node tools/test/run.js        # …through run29.js
```

Each file prints a list of PASS/FAIL lines, reports any JavaScript error the
page threw, and exits non-zero if anything failed. Screenshots land in
`tools/test/shots/`, which is not committed.

They need Playwright and a Chromium; the paths at the top of each file point at
where this project's container keeps them, so adjust those two lines if you run
them somewhere else.

## Before a release

```bash
python3 tools/check_version.py
```

Four places carry the version and they are not near each other. When they
disagree nothing errors — a phone just quietly runs last week's release.
`tools/bump_version.py 2.14.1` sets all four; this asserts they agree.

### One switch the mock owns

The share prompt happens **once ever per browser**, and a fresh Playwright
context is exactly that — so without help it would appear in the middle of
every suite that logs a workout and sit over whatever the test wanted to click
next. `mock-supabase.js` marks it as already asked unless a test opts in with
`window.__ASK_SHARE__ = true`. `run28.js` is the one that opts in.

## The mock is not the server

It answers the same calls, but it is JavaScript pretending to be Postgres. It
has been wrong twice in ways that hid real behaviour — once dropping `badge`
from `my_leagues`, once ignoring which column `order()` was given — so when a
test disagrees with the app, suspect the mock first and check the SQL.

Its `OPEN_TO_ALL` block is generated by `tools/build_bounties.py` from the same
set the server keeps in `bounty_open_to_all()`. Do not edit it by hand: a mock
that allows what the server refuses is a test that passes on a bug.

The rates, categories and muscle shares between `/* BANK BEGIN */` and
`/* BANK END */` are generated by `tools/build_exercises.py` for the same
reason. They used to be hand-written and had already drifted — a plank was
still two points a minute in here long after it was not.

The SQL itself is tested separately, against a real Postgres. See
`supabase/README.md`.

## Seed a rest day, or seed none

A league seeded without `rest_dow` gets the column default, which is Sunday.
On a Sunday the exercise picker offers only stretches and `log_workout`
raises `REST_DAY`, so a suite that merely logs a workout fails one day in
seven for reasons that have nothing to do with what it is testing. Nine of
them did exactly that until it was noticed on a Sunday.

Seed `rest_dow: []` unless the suite is *about* rest days, in which case seed
the day it needs. Never leave it to the default.
